# هم‌گرا

سامانهٔ یکپارچهٔ آزمون‌های شناخت و توسعه: **مسیرنما**، **نقش‌نما** و **تصمیم‌نما** در یک برنامه، با یک ورود، یک فهرست شرکت‌کننده، یک پنل ادمین و یک دیتابیس.

React 19 + Vite + Tailwind 4 در فرانت‌اند؛ توابع Serverless روی Vercel و Neon Postgres در بک‌اند.

## ساختار

```
api/                       توابع Vercel (هر فایل یک مسیر)
  auth.ts                  ورود: شماره تماس + کد ملی (scrypt، قفل پس از ۵ تلاش ناموفق)
  users.ts                 فهرست شرکت‌کنندگان (ادمین): افزودن گروهی/تکی، حذف
  tests.ts                 وضعیت و زمان‌بندی آزمون‌ها (ادمین) و آزمون‌های بازِ هر شرکت‌کننده
  sessions.ts              ثبت نهایی (شرکت‌کننده) و فهرست جلسه‌ها (ادمین)
  analysis.ts              تحلیل پاسخ‌های مسیرنما (ادمین)
  _lib/                    کد مشترک سرور: db، auth، http، زمان‌بندی، و handler هر آزمون (_lib/tests/)
shared/                    کد خالصی که هم مرورگر و هم سرور استفاده می‌کنند (آزمون‌ها، زمان‌بندی، اعتبارسنجی)
src/
  core/                    ورود، فهرست آزمون‌ها، میزبان آزمون، پنل ادمین، کامپوننت‌ها، توکن‌های طراحی
  tests/<id>/              هر آزمون: سؤال‌ها، صفحه‌ها، گزارش، نتایج ادمین
  tests/registry.ts        فهرست آزمون‌ها
tests/                     تست‌ها (روی Postgres واقعی درون‌حافظه)
scripts/dev-api.ts         API محلی بدون Neon
```

## اجرا

```bash
npm install
npm run dev:full    # API محلی (:3001، رمز ادمین «admin») + فرانت (:3000)
npm run dev         # فقط فرانت‌اند (باید API جای دیگری باشد)
npm run lint        # tsc --noEmit
npm test            # تست‌های واحد و API
npm run build
```

`DEV_DEMO_SCORING=1 npm run dev:api` به تصمیم‌نما یک جدول امتیازدهی **ساختگی** می‌دهد تا صفحه‌هایش قابل مشاهده باشد (فقط پیش‌نمایش).

## متغیرهای محیطی (Vercel)

| نام | توضیح |
| --- | --- |
| `DATABASE_URL` | رشتهٔ اتصال Neon |
| `ADMIN_PASSWORD` | گذرواژهٔ پنل مدیریت (`#/admin`)؛ فقط سمت سرور |
| `SESSION_SECRET` | (اختیاری) کلید امضای توکن ورود؛ اگر نباشد از `ADMIN_PASSWORD` مشتق می‌شود |
| `ANTHROPIC_API_KEY` | (اختیاری) برای تحلیل خودکار مسیرنما |
| `ANALYSIS_MODEL` | (اختیاری) مدل تحلیل؛ پیش‌فرض `claude-opus-5-5` |

جدول‌ها (`hamgera_*`) در اولین درخواست خودکار ساخته می‌شوند.

## زمان‌بندی آزمون‌ها

ادمین در `#/admin` ← «آزمون‌ها و زمان‌بندی» برای هر آزمون یکی از این‌ها را انتخاب می‌کند: **بسته** (پیش‌فرض)، **باز (دستی)** یا **زمان‌بندی‌شده** (شروع و پایان اختیاری، به وقت تهران و با تقویم شمسی). باز و بسته بودن را **سرور** تعیین می‌کند؛ ساعت دستگاه شرکت‌کننده اثری ندارد. شرکت‌کننده‌ای که پیش از پایان شروع کرده تا «مهلت تکمیل» (پیش‌فرض ۱۵ دقیقه) بعد از پایان هم می‌تواند ثبت نهایی کند. هر آزمون دو کلید دیگر دارد: «اجازهٔ انجام مجدد» و «نمایش نتیجه به شرکت‌کننده».

## افزودن آزمون جدید

۱. پوشهٔ `src/tests/<id>/` با `Root` (جریان شرکت‌کننده)، `AdminResults` و در صورت نیاز `ResultView`.
۲. `api/_lib/tests/<id>.ts`: اعتبارسنجی ورودی و محاسبهٔ نتیجه روی سرور.
۳. یک ورودی در `shared/tests.ts`، `src/tests/registry.ts` و `api/_lib/tests/index.ts`.
